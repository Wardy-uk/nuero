# Every manifestation of NEURO and SARA — where they stand, 12 Sep 2026

A code-level audit of all eight surfaces, done by reading each client's source and
diffing the routes it actually calls against `backend/server.js`. Nothing here is
taken from a HANDOFF or a commit message. `Wardy-uk/nuero-ios` was cloned fresh at
`ca87d55` (123 commits — it now HAS a remote, which was the top risk in its own
handoff and is closed).

⚠ **This supersedes `docs/handoff-ios-parity-2026-09-11.md`.** That document listed
sixteen server features iOS did not render. iOS has shipped **49 commits since**,
and has closed all but four of them. Read the list below, not that one.

## The tab registries agree

`SaraTabs.swift` and `tabs.jsx` carry the same twelve ids in the same order with
the same default (`surface`) and the same `revealsSecondary` rule. Three shells
(phone, kiosk, iOS) plus the laptop through the phone build. That part is done.

## Gaps — web SARA has it, iOS SARA does not

| Gap | Route | Where it lives on web |
|---|---|---|
| **Friction section** | `GET /api/friction` | `Today.jsx` `FrictionSection`. iOS mentions `friction` only in comments — there is no reader anywhere in the repo. |
| **Whereabouts strip** | `GET /api/signals/room` | the shell top bar on BOTH web shells (`shared-ui/Whereabouts.jsx`). Absent on iOS. |
| **Set an estimate on a running session** | `POST /api/session/estimate` | tapping the "assuming 30 min" line. iOS has every other session verb (`shrink`, `step-away`, `check-in`, `pause`, `resume`, `finish`, `abandon`) and not this one. |
| **Chat streaming** | SSE `GET /api/chat` | iOS is `/api/chat/sync` only. Deliberate per the iOS notes; worth revisiting for long answers. |
| **Tasks: the held lane** | `/api/todos` + `/api/tasks?status=all` | web reads all three and renders the Must-move lane, what the lane held back and why, "Bring it back", and the NEURO snapshot on a row. iOS `SaraTasksView` reads `/api/todos/focus` alone. It HAS defer/undefer with the right four reasons and the MoSCoW/priority/estimate editor — what it lacks is the *reporting* of what was held. |

Server-side TTS (`/api/tts/speak`) is on web and not iOS; that is correct — iOS
speaks on-device with a voice picker, which is better.

## Gaps — iOS has it, the web does not

- **Face ID / biometric gate** in front of both apps.
- **Change the PIN** without signing out (web has sign-out, no change).
- Background HealthKit sync; local notifications with a deliverability check;
  a Live Activity for the running session; on-device outbox receipts.
- **Lock-screen accessory widgets** (`accessoryInline` / `Circular` / `Rectangular`).

## The kiosk is the same app with four things closed

Not gaps — decisions, each enforced in `sara/backend/src/routes/neuroProxy.js`:

- `health` is **not a door** (body data behind an unauthenticated desk screen). The
  Today screen names it as not shown rather than failing.
- `journal`, `vault`, `vault-hygiene`, `plaud` were doors until 11 Sep and no screen
  used them. Closed.
- Nothing outbound: `/api/actions` approve/reject is refused locally.
- Mic and push are **capability**-gated, not device-gated (`speechRecognition.js`,
  `pushUnsupportedReason`), so the same code gives the laptop Electron window no mic
  and says why.

⚠ **`sara/backend` still mounts `/api/actions` ahead of the allowlist** — but the
router is now a stub whose approve/reject/list verbs were removed on 11 Sep, with
the reason written into the file. Verified, not assumed.

## The widgets are the one place Scriptable is still ahead

`sara/widget/neuro-attention.js` (1,572 lines) **fetches `/api/attention` live** with
a token in the iOS Keychain, and renders the agenda, an Open-Meteo forecast,
readiness, the weekly-target ring, a work/personal stack flip and a self-updater.
The native `SaraWidgets` **does not fetch at all** — it renders what the app last
wrote to the App Group, greys out past six hours, and adds her field plus the Live
Activity. Its header says it "finally retires Scriptable"; functionally it does not
yet. Either close the gap or stop saying that.

The Apple Watch remains blocked on Xcode 27's `arm64e` CoreDevice against an Intel
Mac — a hardware fact, not a code one.

## Operational parity, which is not a code question

- `sara/*/dist` is gitignored and built on the target. The Pi kiosk does not update
  itself; on 11 Sep it was three commits behind with a two-day-old `dist` while
  looking entirely healthy. **A parity claim about the kiosk is a claim about what
  is deployed there, not about `main`.**
- The laptop shortcut passes a URL as an argument (`SARA.vbs`), so which build the
  laptop is running is a property of one shortcut and cannot be read from the repo.

## What was done on the back of this audit (12 Sep)

Scanning every web client's `/api/` literals against the real route table — the
check this repo had never had — turned up a **dead route with two live callers**.
`POST /api/jira/flagged/:key` was deleted on 3 Jul 2026 by `48e6481` as a
deliberate product removal; that commit's own message lists the five frontend
files it cleaned up and missed two more. `CapturePanel`'s "Flag Escalation" and
`ImportsPanel`'s `EscalateButton` went on calling it for ten weeks, one showing
`Unexpected token '<'` and the other swallowing the failure into a generic error.

Both removed rather than repointed: the live surface is `EscalationPanel` against
`POST /api/escalation`, which needs a NOVA `reason_code` neither dead control
could supply. Pinned by `backend/routes/client-routes.test.js` — three tests, a
positive control on each scan, both mutation-checked. Full suite 3,128 pass / 0
fail; both frontends build.

**Three of the four iOS gaps are written and pushed** (`nuero-ios` `9aafeb2`):
the estimate on a running session, friction on Today, and the held lane on Tasks
— plus `ISOInstant`, one date parser where there were about to be two. 15 tests
with negative controls. ⚠ **NOT COMPILED**: written on Windows with no Swift
toolchain, so the Mac run is the first real check. See "Building it on the Mac".

**Whereabouts is now ported** (`b8ab095`), after Nick asked for a home for it.
It goes FIRST in Now's existing "Right now, physically" section, beside readiness
and the forecast — same class of fact, no new chrome, already silent when empty.
The provenance the PWA hides in a `title` attribute is rendered as a caption,
because a phone cannot show a tooltip and a bare place name conflates "your watch
was last picked up in the kitchen" with "your phone says Derby".

## The widget, corrected

⚠ **Two corrections to the audit above.** Readiness and the forecast ARE already
native — `SaraWidgets/SensesWidget.swift`, 11 Sep — so the Scriptable-only tiles
were the **weekly-target ring**, the **agenda**, and **live fetch**, not the four
originally listed.

The week now travels on `SharedSnapshot` and renders as NEURO's own sentence plus
a monochrome `Gauge` in `.accessoryCircular` (`b8ab095`). An unset week has no
ring — nil, never zero.

The agenda was **written and then removed**: its only source on that side is
`AttentionFeed.dashboard`, an untyped `AnyPayload` whose `list(key:)` falls back
to "the single array-valued key", which is the net that hid four wrong-key bugs in
the 10 Sep menu audit. A reader with no trustworthy writer is this repo's
signature failure. It goes in when the dashboard is typed.

⚠ **Live fetch is blocked on the CREDENTIAL, not the execution budget.** A widget
extension is a separate process and `Keychain` sets no `kSecAttrAccessGroup`, so
it cannot read the app's PIN. Closing it means a shared keychain-access-group
entitlement on both targets — and an entitlement mistake there fails at INSTALL
and takes the whole app down. That is a decision about where a credential to a
personal server may live, so the header now says what the widget is instead of
claiming to have retired Scriptable.

## Building it on the Mac

```bash
cd ~/Documents/GitHub/nuero-ios && git pull
swift test --package-path NeuroKit            # 353 + 15; models, action, parser
xcodebuild -scheme Sara -destination 'id=00008150-001854EE0E83401C'   -allowProvisioningUpdates                    # the three view changes
```

⚠ `swift test` passing does **not** cover the views — `SessionView` is in
NeuroKit but `SaraTodayView` and `SaraTasksView` are app-target files, so only
`xcodebuild` compiles them. Paste any error back rather than working around it;
the likeliest failures are a SwiftUI `ViewBuilder` nit in one of the two new
sections, not a contract mistake.


## Honest limits of this audit

Every row above was read in source on this machine. What was **not** done: nothing
was run against the live Pi, no iOS build was made (no Mac in this session), and no
screen was looked at. Where the 11 Sep session found bugs by screenshot, that route
is not available here.
